# 0070. Dimension-agnostic design

- **Status:** Accepted
- **Date:** 2026-10-11

## Context
Planets can be defined as datapack dimensions (dimension, dimension type, biomes) and generated by data generation. Space content must work in any dimension without changing v1 systems.

## Options Considered
Planet properties hard-coded versus defined by data; v1 code allowed to check specific dimensions versus reading environment properties only.

## Decision
1. **No hard-coded dimensions:** v1 code never checks for specific dimensions such as `Level.OVERWORLD`; behavior reads environment properties instead (e.g. the solar panel checks daytime and sky access, not the dimension).
2. Networks and machines make no assumption about their dimension (ADR 0028, 0031).
3. Ore generation targets dimensions through tags and biome modifiers (ADR 0053); planet ores later use the same mechanism.
4. Per-player state such as future oxygen uses data attachments (ADR 0024).
5. **Planet environment properties** (gravity, oxygen, temperature, solar factor) will be **data-defined per dimension**, never hard-coded; the exact format is decided when space work starts.

## Consequences
- Architecture tests or reviews reject dimension-specific checks in v1 code.
