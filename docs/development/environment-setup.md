# Development Environment Setup

How to prepare, verify and use the development environment for BTG Tech. Decisions behind these steps: ADR [0010](../decisions/0010-initial-target-minecraft-version.md), [0012](../decisions/0012-build-toolchain.md), [0014](../decisions/0014-primary-ide.md), [0015](../decisions/0015-standard-development-commands.md).

## 1. Reference Machine

Windows 11, repository at `C:\dev\BTGTech`. Shell examples use PowerShell (`.\gradlew.bat <task>`); in Git Bash use `./gradlew <task>`.

## 2. Prerequisites

| Tool | Required version | Verify with | Expected result |
|---|---|---|---|
| JDK | 25 | `java -version` | Reports version `25.x` |
| `JAVA_HOME` | Points to a JDK 25 | `echo $env:JAVA_HOME` | A JDK 25 directory |
| Git | Any recent 2.x | `git --version` | `git version 2.x` |
| GitHub CLI | Any recent 2.x | `gh auth status` | Logged in as `BetelgeuseInteractive` |
| IntelliJ IDEA | 2025.3 or newer (free tier) | Start the IDE | Opens normally |

Gradle is **not** installed globally; the Gradle Wrapper in the repository downloads the pinned version. Other installed JDKs are harmless because the build pins Java 25 through the Gradle toolchain.

## 3. Owner's Manual Steps

These steps involve accepting license agreements or personal choices and are performed by the owner only:

1. Install IntelliJ IDEA (free tier) from jetbrains.com.
2. After the project skeleton exists, open `C:\dev\BTGTech` in IntelliJ IDEA and trust the project.
3. On the first `runServer`, accept the Minecraft EULA by setting `eula=true` in the server run directory's `eula.txt`.

## 4. Project Bootstrap (Phase 0)

Performed once, when Phase 0 starts. Nothing here is executed during planning.

1. Fetch the official template `NeoForgeMDKs/MDK-26.1.2-ModDevGradle` (branch `main`) into a temporary directory **outside** the repository.
2. Copy the build files into the repository root: `build.gradle`, `settings.gradle`, `gradle.properties`, `gradlew`, `gradlew.bat`, `gradle/wrapper/*`, `src/main/templates/META-INF/neoforge.mods.toml`. Never overwrite anything under `docs/`.
3. Do **not** copy the template's example code (`com/example/examplemod/*`), example language file, `README.md` or `TEMPLATE_LICENSE.txt`. `.gitignore`, `.gitattributes` and `.github/workflows/build.yml` are adopted only as decided in planning topic 14.
4. Adapt `gradle.properties`:

   | Key | Value | Source |
   |---|---|---|
   | `minecraft_version` | `26.1.2` | ADR 0010 |
   | `minecraft_version_range` | `[26.1.2]` | ADR 0010 |
   | `neo_version` | Latest stable `26.1.2.x` at bootstrap time (`26.1.2.116` on 2026-10-11) | ADR 0010 |
   | `mod_id` | `btgtech` | ADR 0003 |
   | `mod_name` | `BTG Tech` | ADR 0003 |
   | `mod_license` | `MPL-2.0` | ADR 0013 |
   | `mod_group_id` | `com.betelgeuseinteractive.btgtech` | ADR 0016 |
   | `org.gradle.jvmargs` | `-Xmx4G` | ADR 0015 |

5. Keep the template's ModDevGradle `2.0.148`, Gradle Wrapper `9.2.1` and Java toolchain `25`.
6. Create the mod's entry point and package structure as defined in ADR 0018 and planning topic 5.

## 5. Verification

The environment is ready when all of the following succeed:

| Step | Command | Success criterion |
|---|---|---|
| 1 | `.\gradlew.bat --version` | Gradle 9.2.1 running on JVM 25 |
| 2 | `.\gradlew.bat build` | `BUILD SUCCESSFUL` |
| 3 | `.\gradlew.bat runData` | Completes; output written to `src/generated/resources` |
| 4 | `.\gradlew.bat runGameTestServer` | Exits successfully with all game tests passing |
| 5 | `.\gradlew.bat runClient` | Game reaches the main menu; BTG Tech appears in the mod list |
| 6 | `.\gradlew.bat runServer` | Server starts after the EULA is accepted (owner step 3) |

## 7. IntelliJ IDEA

1. Open the repository folder; IntelliJ detects the Gradle build and imports it.
2. Set **Settings → Build Tools → Gradle → Gradle JVM** to the JDK 25 installation.
3. Run configurations generated by ModDevGradle (client, server, data, game test server) appear after import.
4. Missing Minecraft sources in the editor: re-run the Gradle sync; see the ModDevGradle README section on attaching sources.

## 8. Troubleshooting

| Symptom | Fix |
|---|---|
| Build reports a Java version other than 25 | Check `JAVA_HOME` and IntelliJ's Gradle JVM setting |
| Dependency resolution errors after a version change | `.\gradlew.bat --refresh-dependencies` |
| Stale generated or compiled output | `.\gradlew.bat clean`, then rebuild |
| Server stops immediately on first start | The EULA has not been accepted (owner step 3) |
| Out-of-memory error in Gradle | Confirm `org.gradle.jvmargs=-Xmx4G` in `gradle.properties` |
